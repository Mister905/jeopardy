# Phase 10: Email/Password Sign Up Feature - Implementation Plan

## Description

Add a registration flow to the frontend application to allow new users to sign up with email and password. This feature integrates with Supabase Auth and provides clear UI feedback for success, errors, and loading states. The existing GitHub OAuth login must remain functional alongside the new email/password registration.

## Algorithms and Implementation Steps

### 1. Sign Up Form Implementation

**Problem**: Users need a way to register with email and password, with clear feedback on success and errors.

**Solution**: Add sign up form to login page with toggle between Sign In and Sign Up modes.

**Algorithm**:
```
1. Add state to track current mode (signIn vs signUp):
   - useState<'signIn' | 'signUp'>('signIn')
   - Toggle button to switch between modes

2. In Sign Up mode, render form with:
   - Email input field (type="email", required)
   - Password input field (type="password", required, minLength validation)
   - Confirm password input field (type="password", required)
   - Sign Up button
   - Link/button to switch back to Sign In mode

3. Form validation:
   - Email: Check format using HTML5 validation or regex
   - Password: Check minimum length (e.g., 6+ characters)
   - Confirm password: Must match password field
   - Show validation errors inline

4. On form submit:
   - Prevent default form submission
   - Validate all fields
   - If validation passes:
     a. Set loading state to true
     b. Disable form inputs
     c. Call supabase.auth.signUp({ email, password })
     d. Handle response:
        - If successful:
          - Show success message: "Check your email to verify your account"
          - Optionally redirect to login or show confirmation
        - If error:
          - Extract error message from Supabase error
          - Display user-friendly error message
          - Re-enable form
     e. Set loading state to false
```

### 2. Supabase Sign Up Integration

**Problem**: Need to call Supabase Auth API and handle various error scenarios.

**Solution**: Use `supabase.auth.signUp()` with proper error handling.

**Algorithm**:
```
1. Call supabase.auth.signUp({ email, password }):
   const { data, error } = await supabase.auth.signUp({
     email: emailValue,
     password: passwordValue,
   });

2. Handle response:
   - If error exists:
     a. Check error.message for specific error types:
        - "User already registered" → Show "Email already in use"
        - "Password should be at least 6 characters" → Show password strength error
        - "Invalid email" → Show email format error
        - Network errors → Show "Connection error. Please try again."
     b. Set error state with user-friendly message
     c. Re-enable form
   
   - If successful:
     a. Check if email confirmation is required:
        - If data.user && !data.session:
          → Show: "Please check your email to verify your account"
        - If data.session:
          → User is immediately logged in (if email confirmation disabled)
     b. Set success state
     c. Optionally redirect to games page or show confirmation message
```

### 3. Redux Integration (Optional)

**Problem**: If using Redux for auth state management, need to dispatch sign up actions.

**Solution**: Create auth slice with sign up thunk (optional - can use local state instead).

**Algorithm**:
```
1. Create authSlice.ts with:
   - Initial state:
     {
       signUpLoading: false,
       signUpError: null,
       signUpSuccess: false,
       signUpMessage: null,
     }
   
   - Thunk: signUpUser(email, password):
     a. Set signUpLoading to true
     b. Clear previous errors
     c. Call supabase.auth.signUp()
     d. On success:
        - Set signUpSuccess to true
        - Set signUpMessage to confirmation message
        - Set signUpLoading to false
     e. On error:
        - Set signUpError to error message
        - Set signUpLoading to false

2. In component:
   - Use useAppDispatch to dispatch signUpUser thunk
   - Use useAppSelector to read signUpLoading, signUpError, signUpSuccess
   - Display loading/error/success states from Redux
```

### 4. UI/UX Flow

**Problem**: Users need clear feedback and guidance through the sign up process.

**Solution**: Implement clear visual states and messaging.

**Algorithm**:
```
1. Sign Up Form States:
   - Default: Show form with inputs enabled
   - Loading: Disable inputs, show spinner, change button text to "Signing up..."
   - Error: Show error message above form, keep form enabled
   - Success: Show success message, optionally hide form or show "Check your email" message

2. Toggle between Sign In and Sign Up:
   - Add toggle button/link: "Don't have an account? Sign up" / "Already have an account? Sign in"
   - When toggling:
     - Clear any error/success messages
     - Reset form fields
     - Switch form mode

3. Success Message:
   - Show: "Account created! Please check your email to verify your account before signing in."
   - Optionally add link to resend verification email
   - Show "Back to Sign In" button

4. Error Messages:
   - Display above form in ErrorDisplay component
   - Clear on new submission attempt
   - Show specific messages for:
     - Email already registered
     - Weak password
     - Invalid email format
     - Network errors
```

### 5. Email Verification Flow

**Problem**: Supabase sends verification email automatically, but users need to understand the flow.

**Solution**: Provide clear messaging about email verification.

**Algorithm**:
```
1. After successful sign up:
   - Check if email confirmation is required (Supabase setting):
     - If required: data.user exists but data.session is null
       → Show: "Please check your email and click the verification link"
     - If not required: data.session exists
       → User is logged in, redirect to /games

2. User clicks verification link in email:
   - Supabase redirects to callback URL
   - Existing /auth/callback page handles this
   - User is redirected to /games after verification

3. Optional: Add resend verification email feature:
   - Button: "Resend verification email"
   - Call supabase.auth.resend({ type: 'signup', email })
   - Show confirmation: "Verification email sent"
```

## Error Handling

### Supabase Auth Errors

1. **Email already registered**:
   - Error code: Usually in error.message
   - Display: "This email is already registered. Please sign in instead."
   - Action: Show link to sign in mode

2. **Weak password**:
   - Error message: "Password should be at least X characters"
   - Display: Show password requirements
   - Action: Highlight password field, show requirements

3. **Invalid email format**:
   - Error message: "Invalid email"
   - Display: "Please enter a valid email address"
   - Action: Highlight email field

4. **Network errors**:
   - Error: Network failure or timeout
   - Display: "Connection error. Please check your internet and try again."
   - Action: Allow retry

5. **Rate limiting**:
   - Error: Too many requests
   - Display: "Too many sign up attempts. Please try again later."
   - Action: Disable form temporarily

## Implementation Notes

1. **Password Requirements**:
   - Supabase default: Minimum 6 characters
   - Can be configured in Supabase dashboard
   - Consider showing requirements to user: "Password must be at least 6 characters"

2. **Email Confirmation**:
   - Supabase can be configured to require email confirmation
   - If enabled, user must verify email before signing in
   - If disabled, user is immediately logged in after sign up

3. **Optional Features**:
   - Password strength indicator (weak/medium/strong)
   - Show/hide password toggle
   - Remember me checkbox (for sign in mode)
   - Social login buttons (GitHub already exists)

4. **Accessibility**:
   - Use proper form labels
   - Use ARIA attributes for error messages
   - Ensure keyboard navigation works
   - Ensure screen reader announcements for errors

5. **Security**:
   - Never log passwords
   - Use HTTPS (handled by Supabase)
   - Validate on both client and server (Supabase handles server validation)
   - Consider rate limiting (Supabase handles this)
