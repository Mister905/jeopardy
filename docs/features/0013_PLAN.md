# Transition Jeopardy Game Data Ingestion Away from Cluebase API

## Description

Replace the unreliable Cluebase API integration with local TSV file parsing and ingestion for Jeopardy and Double Jeopardy clues. The Cluebase API has proven unreliable due to connection errors, downtime, and SSL/TLS issues. This transition uses existing raw TSV files in `backend/data/jeopardy_clue_dataset/raw` to extract non-Final Jeopardy clues (rounds 1 and 2) and ingest them into the local database. Game initialization logic will be updated to pull clues from the local database instead of the Cluebase API. Final Jeopardy ingestion remains separate and unchanged.

## Implementation Algorithm

### Phase 1: Parser Service Implementation

1. **Create JeopardyParserService**
   - Reuse TSV parsing logic from `FinalJeopardyParserService`
   - Filter for `round = '1'` (Jeopardy) and `round = '2'` (Double Jeopardy)
   - Parse `clue_value` column as integer for dollar value
   - Parse `daily_double_value` column: if > 0, set `dailyDouble = true`
   - Validate dollar values match round requirements:
     - Jeopardy (round=1): values must be 200, 400, 600, 800, or 1000
     - Double Jeopardy (round=2): values must be 400, 800, 1200, 1600, or 2000
   - Validate required fields: `category`, `answer`, `question` must be non-empty
   - Extract season number from filename (season33.tsv → 33)
   - Output to `backend/data/jeopardy_clue_dataset/parsed/jeopardy-clues.json`

2. **Data Normalization**
   - Map TSV columns to parsed clue structure:
     - `round` → `round` ('1' or '2')
     - `clue_value` → `value` (integer)
     - `daily_double_value` → `dailyDouble` (boolean: true if > 0)
     - `category` → `category` (trimmed)
     - `answer` → `answer` (trimmed)
     - `question` → `question` (trimmed)
     - `air_date` → `airDate` (optional)
   - Create deduplication key: `${round}|${category}|${question}|${answer}`

### Phase 2: Ingestion Service Implementation

1. **Create JeopardyIngestionService**
   - Read parsed JSON file from `backend/data/jeopardy_clue_dataset/parsed/jeopardy-clues.json`
   - Validate each clue:
     - Required fields: `category`, `answer`, `question`, `value`, `round`
     - Dollar value matches round requirements
     - Round is '1' or '2'
   - Check for existing clues in database using deduplication key
   - Batch insert new clues to database:
     - Map `round` string ('1' or '2') to `Round` enum (JEOPARDY or DOUBLE_JEOPARDY)
     - Set `value` from parsed clue
     - Set `dailyDouble` from parsed clue
     - Set `category`, `question`, `answer` (trimmed)
   - Handle duplicates gracefully (skip if already exists)
   - Log ingestion results (total processed, inserted, duplicates skipped, errors)

2. **Database Persistence**
   - Use Prisma `Clue` model with:
     - `round: Round.JEOPARDY` or `Round.DOUBLE_JEOPARDY`
     - `value: number` (from parsed clue)
     - `dailyDouble: boolean` (from parsed clue)
     - `category: string`, `question: string`, `answer: string`
   - Use existing duplicate detection index: `@@index([round, category, question, answer])`
   - Insert in batches to avoid transaction timeouts

### Phase 3: Game Service Updates

1. **Remove Cluebase Dependencies**
   - Remove `CluebaseService` from constructor injection
   - Remove `private readonly cluebaseService: CluebaseService` field
   - Remove `CluebaseModule` import from `GameModule`

2. **Update `startGame()` Method**
   - Remove Step 1: `await this.cluebaseService.fetchAndPersistClues(Round.JEOPARDY, ...)`
   - Remove Step 2: `await this.cluebaseService.fetchAndPersistClues(Round.DOUBLE_JEOPARDY, ...)`
   - Keep existing logic for:
     - Step 3: Select categories for Jeopardy round (from database)
     - Step 4: Select categories for Double Jeopardy round (from database)
     - Step 5: Get clues for selected categories with Daily Doubles
   - Add validation to ensure sufficient clues exist in database:
     - If `selectCategoriesForRound()` fails or returns insufficient categories, throw error with message referencing local database ingestion instead of Cluebase API
   - Update error messages to reference local database instead of Cluebase API

3. **Verify Existing Methods**
   - Ensure `selectCategoriesForRound()` works with locally ingested clues
   - Ensure `getCluesForCategories()` works with locally ingested clues
   - Both methods should already work since they query the database, but verify error messages are updated

## Data Validation Rules

### Round 1 (Jeopardy) Clues
- `round` must equal '1'
- `clue_value` must be one of: 200, 400, 600, 800, 1000
- `category`, `answer`, `question` must be non-empty after trimming

### Round 2 (Double Jeopardy) Clues
- `round` must equal '2'
- `clue_value` must be one of: 400, 800, 1200, 1600, 2000
- `category`, `answer`, `question` must be non-empty after trimming

### Daily Double Detection
- If `daily_double_value > 0`, set `dailyDouble = true`
- If `daily_double_value = 0`, set `dailyDouble = false`
- Daily Double clues must still have valid dollar values for their round

## Error Handling

### Parser Errors
- Log malformed TSV rows with file name and line number
- Skip invalid rows and continue processing
- Collect all errors and include in parsing result

### Ingestion Errors
- Log validation errors for individual clues
- Skip duplicate clues (already in database)
- Handle database insertion errors gracefully
- Continue processing remaining clues if a batch fails

### Game Initialization Errors
- If insufficient clues in database, throw error: "Insufficient clues in database for [ROUND] round. Please run the Jeopardy ingestion script: npm run ingest:jeopardy"
- Ensure error messages no longer reference Cluebase API
