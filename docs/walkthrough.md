# Manual Setup + Cursor Workflow

The goal is to ultimately remove ambiguity before it can cost you time.

- `create_brief.md` → locks intent
- `business_rules.md` → locks behavior
- `design_schema.md` → locks Prisma models
- `plan_feature.md` → plans implementation
- Cursor implementation → writes code

## Backend + Prisma Environment

### Scaffold NestJS backend

```bash
npx @nestjs/cli new backend
cd backend
```

### Install dependencies

```bash
npm install @nestjs/config @prisma/client prisma
```

### Initialize Prisma

```bash
npx prisma init
# Creates prisma/schema.prisma and .env
```

### Create Supabase project

Copy Session pooler connection string (IPv4-compatible)

Set in `.env`:

```env
DATABASE_URL="postgresql://postgres:[PROJECT_ID]:[PASSWORD]@[POOLER_URL]:5432/postgres"
```

### Configure NestJS to load .env

```typescript
// app.module.ts
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [ConfigModule.forRoot({ isGlobal: true })],
})
export class AppModule {}
```

### Replace prisma/schema.prisma

Use Cursor-generated schema

### Run Prisma migration

```bash
npx prisma migrate dev --name init
# Creates tables in Supabase and generates Prisma Client
```

### Generate Prisma client

```bash
npx prisma generate
```

### Create Prisma module and service

```bash
npx nest g module prisma
npx nest g service prisma
```

### Implement PrismaService

```typescript
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit {
  async onModuleInit() {
    await this.$connect();
  }
}
```

### Export PrismaService

```typescript
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
```

## Feature Planning + Cursor Implementation

### Create plan_feature.md

```bash
touch plan_feature.md
# Describe feature: e.g., Create Game endpoint
```

### Cursor prompt to plan remaining features

```text
@implementation_roadmap.md

@plan_feature.md

Feature: Final Jeopardy File Parsing Service

Purpose: Implement a robust parsing service that processes all raw TSV clue files for Final Jeopardy, validates, normalizes, and writes cleaned data for later database ingestion.

Inputs:
- Raw TSV files in backend/data/jeopardy_clue_dataset/raw
- Columns: round, clue_value, daily_double_value, category, comments, answer, question, air_date, notes

Outputs:
- JSON files in backend/data/jeopardy_clue_dataset/parsed
- Metadata including counts of total, valid, invalid, and duplicate rows

Rules:
- Only round = 3 rows are included
- category, answer, question must be non-empty after trimming
- Deduplicate by composite key: category|question|answer
- Log all errors, duplicates, and summary stats

Dependencies:
- Node.js file system
- TypeScript interfaces in types.ts
- Optional: path/environment variables for robustness

Algorithm:
1. Discover raw files
2. Parse TSV rows
3. Filter Final Jeopardy clues
4. Validate required fields
5. Normalize data
6. Deduplicate (optional)
7. Write output JSON
8. Log metadata and errors
```

## Required Packages for Supabase Auth Integration

The following packages need to be installed for the authentication implementation:

```bash
npm install @supabase/supabase-js jsonwebtoken
npm install --save-dev @types/jsonwebtoken
```

### Packages

1. **@supabase/supabase-js** - Supabase client library for initializing the Supabase client
2. **jsonwebtoken** - JWT library for verifying Supabase JWT tokens
3. **@types/jsonwebtoken** - TypeScript type definitions for jsonwebtoken

### Environment Variables Required

Make sure to set the following environment variables:

- `SUPABASE_URL` - Your Supabase project URL
- `SUPABASE_ANON_KEY` - Your Supabase anonymous/public key
- `SUPABASE_JWT_SECRET` - Your Supabase JWT secret (found in Project Settings → API → JWT Secret)
