# Phase 11: Replace OAuth with Email/Password Authentication - Implementation Plan

## Description

Replace the existing GitHub OAuth login system with a standalone email/password authentication flow using Supabase Auth. Remove all OAuth functionality and implement sign up, sign in, and sign out using email and password. Redux can be used to track auth state if needed.

## Files to Modify

### Auth Pages
- `frontend/src/app/auth/login/page.tsx` - Login page
  - Remove `signInWithOAuth` call and GitHub OAuth button
  - Remove OAuth-related comments and code
  - Add email input field (type="email", required)
  - Add password input field (type="password", required)
  - Add "Sign In" button that calls `supabase.auth.signInWithPassword({ email, password })`
  - Add "Sign Up" button or toggle to switch to sign up mode
  - Show error messages for invalid credentials, network errors, etc.
  - Show loading state during authentication
  - Optionally: Add toggle between Sign In and Sign Up modes in same page

- `frontend/src/app/auth/callback/page.tsx` - Auth callback page
  - Remove OAuth-specific handling (if any)
  - Keep session checking logic (works for both OAuth and email/password)
  - Update comments to reflect email/password flow
  - This page can still handle email verification redirects from Supabase

### Redux / State
- `frontend/src/store/authSlice.ts` - New Redux slice for auth state
  - State interface:
    - `signInLoading: boolean`
    - `signInError: string | null`
    - `signUpLoading: boolean`
    - `signUpError: string | null`
    - `signUpSuccess: boolean`
    - `signUpMessage: string | null`
    - `user: AuthenticatedUser | null` (optional - can use hooks instead)
  - Thunks:
    - `signUpUser({ email, password })` - Calls `supabase.auth.signUp({ email, password })`
    - `signInUser({ email, password })` - Calls `supabase.auth.signInWithPassword({ email, password })`
    - `signOutUser()` - Calls `supabase.auth.signOut()`
  - ExtraReducers: Handle `pending`, `fulfilled`, and `rejected` states for each thunk
  - Remove any OAuth-related thunks or state (if they exist)

- `frontend/src/store/store.ts` - Redux store configuration
  - Add `authSlice` reducer to store
  - Export auth-related types and selectors

### Supabase Integration
- `frontend/src/lib/auth/supabase.ts` - Supabase client (no changes needed)
  - Keep existing Supabase client instance
  - Remove any OAuth helper functions (if they exist)
  - Auth thunks will call:
    - `supabase.auth.signUp({ email, password })` for registration
    - `supabase.auth.signInWithPassword({ email, password })` for sign in
    - `supabase.auth.signOut()` for sign out

### Auth Hooks (Optional Updates)
- `frontend/src/lib/auth/hooks.ts` - Auth hooks
  - Keep existing `useAuth()` and `useRequireAuth()` hooks (they work with any auth method)
  - No changes needed - hooks use `supabase.auth.getSession()` and `onAuthStateChange` which work for all auth methods
  - Optionally: Add Redux integration if using authSlice

### Types
- `frontend/src/types/auth.ts` - Auth types (no changes needed)
  - Existing `AuthenticatedUser` interface is sufficient
  - No OAuth-specific types to remove

## Algorithms and Implementation Steps

### 1. Remove OAuth Code

**Problem**: GitHub OAuth login needs to be completely removed from the codebase.

**Solution**: Remove all OAuth-related code and replace with email/password forms.

**Algorithm**:
```
1. In login/page.tsx:
   a. Remove handleLogin function that calls signInWithOAuth
   b. Remove "Sign in with GitHub" button
   c. Remove OAuth-related comments
   d. Remove redirectTo callback URL logic (OAuth-specific)

2. Search codebase for OAuth references:
   a. Remove any signInWithOAuth calls
   b. Remove any GitHub provider references
   c. Remove OAuth redirect handling (if separate from callback)
   d. Update comments that mention OAuth

3. In callback/page.tsx:
   a. Keep session checking logic (works for email/password too)
   b. Remove OAuth-specific comments
   c. Update to handle email verification redirects (if Supabase sends them here)
```

### 2. Sign Up Implementation

**Problem**: Users need to register with email and password.

**Solution**: Add sign up form and integrate with Supabase Auth.

**Algorithm**:
```
1. Add sign up form to login page (or create separate page):
   a. Email input field:
      - type="email"
      - required
      - Validate email format
   b. Password input field:
      - type="password"
      - required
      - Minimum length validation (6+ characters, Supabase default)
   c. Confirm password field (optional but recommended):
      - type="password"
      - required
      - Must match password field
   d. "Sign Up" button

2. Form validation:
   a. Email: Check format (HTML5 validation or regex)
   b. Password: Check minimum length
   c. Confirm password: Must match password
   d. Show validation errors inline

3. On Sign Up submit:
   a. Prevent default form submission
   b. Validate all fields
   c. If validation passes:
      - Set loading state to true
      - Disable form inputs
      - Dispatch signUpUser thunk (or call supabase.auth.signUp directly)
      - Handle response:
         * If successful:
           - Check if email confirmation required:
             - If data.user && !data.session:
               → Show: "Please check your email to verify your account"
             - If data.session:
               → User logged in immediately, redirect to /games
         * If error:
           - Extract error message
           - Display user-friendly error:
             * "Email already registered" for existing email
             * "Password should be at least 6 characters" for weak password
             * "Invalid email" for email format errors
           - Re-enable form
      - Set loading state to false
```

### 3. Sign In Implementation

**Problem**: Users need to sign in with email and password.

**Solution**: Add sign in form and integrate with Supabase Auth.

**Algorithm**:
```
1. Add sign in form to login page:
   a. Email input field:
      - type="email"
      - required
   b. Password input field:
      - type="password"
      - required
   c. "Sign In" button

2. On Sign In submit:
   a. Prevent default form submission
   b. Validate email format
   c. If validation passes:
      - Set loading state to true
      - Disable form inputs
      - Dispatch signInUser thunk (or call supabase.auth.signInWithPassword directly)

         * If successful:
           - Check data.session:
             - If session exists:

             - If no session:

```

### 4. Redux Auth Slice Implementation

**Problem**: Need centralized auth state management with loading/error states.

**Solution**: Create Redux slice with thunks for sign up, sign in, and sign out.

**Algorithm**:
```
1. Create authSlice.ts:
   a. Define initial state:
      {
        signInLoading: false,
        signInError: null,
        signUpLoading: false,
        signUpError: null,
        signUpSuccess: false,
        signUpMessage: null,
        user: null, // Optional - can use hooks instead
      }

   b. Create signUpUser thunk:
      - Accept { email, password }
      - Set signUpLoading to true (pending)
      - Clear signUpError
      - Call supabase.auth.signUp({ email, password })
      - On success (fulfilled):
        * Set signUpSuccess to true
        * Set signUpMessage based on email confirmation requirement
        * Set signUpLoading to false
      - On error (rejected):
        * Extract error message
        * Set signUpError to user-friendly message
        * Set signUpLoading to false

   c. Create signInUser thunk:
      - Accept { email, password }
      - Set signInLoading to true (pending)
      - Clear signInError
      - Call supabase.auth.signInWithPassword({ email, password })
      - On success (fulfilled):
        * Check if session exists
        * If session: User is logged in (handled by onAuthStateChange)
        * Set signInLoading to false
      - On error (rejected):
        * Extract error message
        * Set signInError to user-friendly message
        * Set signInLoading to false

   d. Create signOutUser thunk:
      - Set loading state (optional)
      - Call supabase.auth.signOut()
      - On success: Clear user state
      - On error: Set error state

2. Add authSlice to store.ts:
   - Import authReducer
   - Add to reducer object: { auth: authReducer, game: gameReducer }
```

### 5. Sign Out Implementation

**Problem**: Users need to sign out of their account.

**Solution**: Call Supabase sign out and clear auth state.

**Algorithm**:
```
1. In Header component or wherever sign out is triggered:
   a. Dispatch signOutUser thunk (or call supabase.auth.signOut directly)
   b. On success:
      - User state cleared (handled by onAuthStateChange)
      - Redirect to /auth/login
   c. On error:
      - Show error message
      - Optionally force redirect anyway
```

**Problem**: Users need clear feedback and easy navigation between sign in and sign up.

**Solution**: Implement toggle or separate views with clear messaging.

**Algorithm**:
```
1. Option A: Toggle in same page:
   a. Add state: useState<'signIn' | 'signUp'>('signIn')
   b. Show appropriate form based on mode
   c. Add toggle link: "Don't have an account? Sign up" / "Already have an account? Sign in"
   d. When toggling: Clear errors, reset form

2. Option B: Separate pages:
   a. Keep login/page.tsx for sign in
   b. Create signup/page.tsx for sign up
   c. Add navigation links between pages

3. Success/Error Messages:
   a. Sign Up Success:
      - "Account created! Please check your email to verify your account."
      - Show "Back to Sign In" button

      - Redirect to /games (no message needed)

      - Display in ErrorDisplay component
      - Clear on new submission attempt
```

### 7. Email Verification Handling

**Problem**: Supabase may require email verification before users can sign in.

**Solution**: Handle email verification flow and provide clear messaging.

**Algorithm**:
```
1. After sign up:
   a. Check response:
      - If data.user && !data.session:
        → Email confirmation required
        → Show: "Please check your email and click the verification link"
      - If data.session:
        → Email confirmation not required
        → User logged in immediately

2. Email verification link:
   a. Supabase sends email with verification link
   b. Link redirects to callback URL (configured in Supabase)
   c. Callback page checks session:
      - If session exists: Redirect to /games
      - If no session: Redirect to /auth/login with message

3. Optional: Resend verification email:
   a. Add "Resend verification email" button
   b. Call supabase.auth.resend({ type: 'signup', email })
   c. Show confirmation message
```

## Error Handling

### Supabase Auth Errors

1. **Sign Up Errors**:
   - "User already registered" → "This email is already registered. Please sign in instead."
   - "Password should be at least 6 characters" → "Password must be at least 6 characters long."
   - "Invalid email" → "Please enter a valid email address."
   - Network errors → "Connection error. Please check your internet and try again."

2. **Sign In Errors**:
   - "Invalid login credentials" → "Invalid email or password."
   - "Email not confirmed" → "Please verify your email before signing in."
   - "Too many requests" → "Too many sign in attempts. Please try again later."
   - Network errors → "Connection error. Please check your internet and try again."

3. **Sign Out Errors**:
   - Network errors → "Failed to sign out. Please try again."
   - Handle gracefully - can still redirect to login

## Implementation Notes

1. **Password Requirements**:
   - Supabase default: Minimum 6 characters
   - Can be configured in Supabase dashboard
   - Show requirements to user: "Password must be at least 6 characters"

2. **Email Confirmation**:
   - Configurable in Supabase dashboard
   - If enabled: User must verify email before signing in
   - If disabled: User logged in immediately after sign up

3. **Session Management**:
   - Supabase handles session persistence automatically
   - `onAuthStateChange` hook updates user state automatically
   - No manual session storage needed

4. **Callback Page**:
   - Can be used for email verification redirects
   - Supabase redirects to configured callback URL after email verification
   - Page checks session and redirects appropriately

5. **Optional Features**:
   - "Remember me" checkbox (Supabase handles this automatically)
   - Show/hide password toggle
   - Password strength indicator
   - Forgot password flow (future feature)
