# Supabase Auth Verification & Testing Plan

## Description

Verify and test that Supabase Auth integration is fully functional. Confirm JWT verification works correctly, guards enforce authentication, CurrentUser decorator extracts userId properly, and all error scenarios are handled. This includes unit tests, integration tests, and end-to-end verification of the authentication flow.

## Files to Create

- `backend/src/auth/__tests__/auth.e2e-spec.ts` - End-to-end tests for authentication flow
- `backend/src/auth/__tests__/test-helpers/jwt-token-generator.ts` - Utility to generate test JWT tokens
- `backend/src/auth/__tests__/test-helpers/test-controller.ts` - Test controller with protected routes for testing
- `backend/src/auth/__tests__/test-helpers/test-controller.spec.ts` - Tests for test controller (if needed)

## Files to Modify

- `backend/src/auth/supabase.service.spec.ts` - Enhance existing unit tests if needed
- `backend/src/auth/auth.guard.spec.ts` - Enhance existing unit tests if needed
- `backend/src/auth/decorators/current-user.decorator.spec.ts` - Enhance existing unit tests if needed
- `backend/src/app.module.ts` - Temporarily register test controller for E2E tests (or use separate test module)
- `backend/test/jest-e2e.json` - Ensure E2E test configuration is correct

## Data Structure

### Test JWT Token Payload

```typescript
interface TestJwtPayload {
  sub: string; // User ID
  email?: string;
  aud: string; // "authenticated"
  exp: number; // Expiration timestamp
  iat: number; // Issued at timestamp
}
```

### Test Environment Variables

Tests should use test environment variables or mock values:
- `SUPABASE_URL` - Test Supabase URL (can be placeholder for unit tests)
- `SUPABASE_ANON_KEY` - Test anon key (can be placeholder for unit tests)
- `SUPABASE_JWT_SECRET` - Test JWT secret (must match token generation)

## Algorithm

### Step 1: Create JWT Token Generator Utility

1. Create utility function to generate JWT tokens for testing
2. Use `jsonwebtoken` library with `SUPABASE_JWT_SECRET` from environment
3. Support generating:
   - Valid tokens with proper claims (sub, aud, exp, iat)
   - Expired tokens (exp in the past)
   - Tokens with missing required claims (e.g., missing sub)
   - Tokens signed with wrong secret (for invalid token tests)
4. Function signature: `generateTestToken(payload: TestJwtPayload, options?: { expiresIn?: number, secret?: string }): string`

### Step 2: Create Test Controller

1. Create a test controller with protected and public routes:
   - `GET /test/protected` - Protected route requiring authentication
   - `GET /test/public` - Public route (marked with @Public())
   - `GET /test/current-user` - Protected route that returns current user info
2. Use `@UseGuards(AuthGuard)` on protected routes
3. Use `@CurrentUser()` decorator to extract user in protected routes
4. Return appropriate responses to verify authentication worked

### Step 3: Unit Test Verification

1. **SupabaseService Tests**:
   - Verify `verifyToken()` with valid token returns correct AuthenticatedUser
   - Verify `verifyToken()` with invalid token throws error
   - Verify `verifyToken()` with expired token throws error
   - Verify `verifyToken()` with missing sub claim throws error
   - Verify `verifyToken()` with wrong secret throws error
   - Verify error messages are descriptive

2. **AuthGuard Tests**:
   - Verify guard extracts token from `Authorization: Bearer <token>` header
   - Verify guard throws UnauthorizedException when token is missing
   - Verify guard throws UnauthorizedException when token is invalid
   - Verify guard throws UnauthorizedException when token is expired
   - Verify guard attaches AuthenticatedUser to request when token is valid
   - Verify guard allows request to proceed when token is valid
   - Verify guard bypasses authentication for @Public() routes
   - Verify guard handles malformed Authorization header

3. **CurrentUser Decorator Tests**:
   - Verify decorator extracts AuthenticatedUser from request
   - Verify decorator throws error when user is not in request
   - Verify extracted userId matches token's sub claim
   - Verify email is extracted if present in token

### Step 4: Integration/E2E Test Implementation

1. **Setup Test Application**:
   - Create NestJS test application with AuthModule and test controller
   - Configure test environment variables (or use mocks)
   - Initialize test application before each test

2. **Test Protected Route Without Token**:
   - Send GET request to `/test/protected` without Authorization header
   - Verify response status is 401 Unauthorized
   - Verify response body contains appropriate error message

3. **Test Protected Route With Invalid Token**:
   - Generate token with wrong secret
   - Send GET request to `/test/protected` with invalid token
   - Verify response status is 401 Unauthorized
   - Verify error message indicates invalid token

4. **Test Protected Route With Expired Token**:
   - Generate expired token (exp in the past)
   - Send GET request to `/test/protected` with expired token
   - Verify response status is 401 Unauthorized
   - Verify error message indicates expired token

5. **Test Protected Route With Valid Token**:
   - Generate valid token with test userId
   - Send GET request to `/test/protected` with valid token
   - Verify response status is 200 OK
   - Verify request was allowed to proceed

6. **Test CurrentUser Decorator**:
   - Generate valid token with known userId and email
   - Send GET request to `/test/current-user` with valid token
   - Verify response status is 200 OK
   - Verify response body contains correct userId
   - Verify response body contains correct email (if present in token)

7. **Test Public Route**:
   - Send GET request to `/test/public` without token
   - Verify response status is 200 OK
   - Verify authentication was bypassed

8. **Test UserId Consistency**:
   - Generate token with specific userId
   - Send request to protected route that uses @CurrentUser()
   - Verify userId extracted matches token's sub claim
   - Verify userId can be passed to domain service correctly

### Step 5: Logging Verification

1. Verify AuthGuard logs errors appropriately:
   - Missing token → warning log
   - Invalid token → warning log
   - Expired token → warning log
2. Verify SupabaseService logs token verification:
   - Successful verification → debug log with userId
   - Failed verification → error log with details
3. Verify logs don't expose sensitive information (tokens, secrets)

### Step 6: Error Response Verification

1. Verify all 401 responses have consistent format:
   - Status code: 401
   - Error message indicates authentication failure
   - No sensitive information in error messages
2. Verify error messages are user-friendly (not exposing internal details)

## Testing Strategy

### Unit Tests

1. **JWT Token Generator**:
   - Test valid token generation
   - Test expired token generation
   - Test token with custom claims
   - Test token with wrong secret

2. **SupabaseService** (enhance existing):
   - All token verification scenarios
   - Error handling and logging
   - Configuration validation

3. **AuthGuard** (enhance existing):
   - Token extraction from headers
   - All error scenarios
   - Public route bypass
   - Request attachment

4. **CurrentUser Decorator** (enhance existing):
   - User extraction
   - Error handling
   - Type safety

### Integration/E2E Tests

1. **End-to-End Authentication Flow**:
   - Complete request flow with valid token
   - Verify guard → service → decorator chain works
   - Verify userId is correctly passed through

2. **Error Scenarios**:
   - Missing token → 401
   - Invalid token → 401
   - Expired token → 401
   - Malformed header → 401

3. **Public Route Bypass**:
   - Verify @Public() decorator works
   - Verify public routes don't require authentication

4. **UserId Extraction and Passing**:
   - Verify @CurrentUser() extracts correct userId
   - Verify userId matches token's sub claim
   - Verify userId can be used in controller and passed to services

## Error Handling

### Expected Error Responses

1. **Missing Token**:
   - Status: 401 Unauthorized
   - Message: "Authorization token is required"

2. **Invalid Token**:
   - Status: 401 Unauthorized
   - Message: "Invalid or expired token"

3. **Expired Token**:
   - Status: 401 Unauthorized
   - Message: "Invalid or expired token"

4. **Malformed Header**:
   - Status: 401 Unauthorized
   - Message: "Authorization token is required"

### Logging Requirements

1. All authentication failures should be logged
2. Logs should include:
   - Error type (missing, invalid, expired)
   - Request path (if available)
   - Timestamp
3. Logs should NOT include:
   - Full JWT tokens
   - JWT secrets
   - Sensitive user data

## Constraints

- **Test isolation**: Each test should be independent and not rely on other tests
- **No real Supabase calls**: Unit tests should mock SupabaseService, E2E tests can use test tokens
- **Environment variables**: Tests should work with test/placeholder values
- **Cleanup**: Test controllers and routes should be clearly marked as test-only
- **Performance**: Tests should run quickly (avoid real network calls in unit tests)

## Exit Conditions

The Supabase Auth verification and testing is complete when:

- All unit tests pass for SupabaseService, AuthGuard, and CurrentUser decorator
- All integration/E2E tests pass for protected routes
- Protected routes correctly reject unauthenticated requests (401)
- Protected routes correctly accept valid JWT tokens (200)
- Invalid/expired tokens correctly return 401 Unauthorized
- Public routes correctly bypass authentication
- @CurrentUser() decorator correctly extracts userId from valid tokens
- userId extracted matches token's sub claim
- userId can be correctly passed to domain services
- Error responses are consistent and user-friendly
- Logging works correctly for all scenarios
- No sensitive information is exposed in logs or error messages
- All test utilities (JWT generator) work correctly

The authentication system is verified and ready for use when:
- All tests pass
- Documentation confirms expected behavior
- Error handling is robust and secure
- Logging provides useful debugging information without exposing secrets
