## Algorithms and State Management

### 1. Automatic State Refresh

**Problem**: UI doesn't automatically reflect backend state changes after actions or state transitions.

**Solution**: Implement automatic polling for active games:
- Poll every 2-3 seconds when game is in ACTIVE, FINAL_PENDING, or FINAL_ACTIVE states
- Stop polling when game is COMPLETED or ELIMINATED
- Stop polling when user is interacting (actionLoading is true)
- Use `useEffect` with cleanup to manage polling interval

**Algorithm**:
```
1. On component mount or game state change:
   a. Dispatch Redux thunk to initialize game state
   b. Redux thunk checks game state:
      - If ACTIVE, FINAL_PENDING, or FINAL_ACTIVE:
        - Dispatch startPolling action
        - Set up polling interval in Redux middleware or thunk
        - Polling dispatches fetchGameData thunk every 2-3 seconds
        - fetchGameData thunk updates Redux store with fresh data
      - If COMPLETED or ELIMINATED:
        - Dispatch stopPolling action
        - Fetch final state once via fetchGameData thunk

2. On user action (answer clue, submit wager, etc.):
   a. Dispatch Redux thunk (e.g., answerClue, submitClueWager)
   b. Thunk sets actionLoading to true in Redux store
   c. Thunk pauses polling temporarily
   d. Thunk executes API call
   e. Thunk dispatches fetchGameData to refresh state
   f. Thunk sets actionLoading to false
   g. Thunk re-enables polling if game still active

3. Cleanup:
   - Dispatch stopPolling action on component unmount
   - Redux middleware clears polling interval
   - All state cleanup handled by Redux slice
```

### 2. Clue Selection Flow

**Problem**: When clicking an UNANSWERED clue, the question may not be available in board response, requiring a separate API call.

**Solution**: 
- Always fetch full game data when selecting a clue to ensure question is available
- Use gameClues from game response which includes full clue details
- Fallback to board data if game data unavailable

**Algorithm**:
```
1. User clicks clue:
   a. Dispatch selectClue Redux thunk with clueId and gameClueId
   b. Thunk reads current board state from Redux store
   c. Thunk checks if clue data exists in board state
   d. If UNANSWERED and question missing:
      - Thunk dispatches fetchGameData to get full game data
      - Thunk finds gameClue matching gameClueId in Redux game state
      - Thunk extracts question from gameClue.clue.question
   e. Thunk dispatches setSelectedClue action with complete data
   f. All components reading selectedClue from Redux automatically update

2. Display clue modal (component reads from Redux):
   - Component reads selectedClue from Redux store
   - If UNANSWERED + Daily Double: Show wager input
   - If UNANSWERED + Regular: Show question immediately
   - If ANSWERED: Show answer adjudication
   - If RESOLVED: Show read-only view
```

### 3. Wager Input Max Value

**Problem**: WagerInput uses placeholder calculation `Math.max(game.score, 1000)` instead of backend-provided maxWager.

**Solution**: 
- Extract maxWager from backend response (SubmitWagerResponse.maxWager)
- Pass maxWager as prop to WagerInput component
- For Daily Double, fetch maxWager from backend before showing input
- For Final Jeopardy, maxWager equals current score (already correct)

**Algorithm**:
```
1. Daily Double wager flow:
   a. User clicks Daily Double clue
   b. Fetch current game state to get score
   c. Show WagerInput with:
      - minWager: 5
      - maxWager: From backend response after wager submission attempt, or calculate as max(score, roundHighestValue)
      - Note: Backend validates, so we can use reasonable estimate initially

2. Final Jeopardy wager flow:
   a. maxWager = currentScore (already correct)
   b. minWager = 0
```

### 4. Round Transition Handling

**Problem**: When all clues in a round are answered, game transitions to next round, but UI may not reflect this immediately.

**Solution**:
- Detect round completion by checking if all clues in current round are RESOLVED
- Automatically refresh state when round completion detected
- Handle transition from ACTIVE → FINAL_PENDING → FINAL_ACTIVE

**Algorithm**:
```
1. After each clue answer:
   a. Redux thunk (answerClue) dispatches fetchGameData to refresh state
   b. Redux store is updated with new game and board state
   c. Redux reducer checks if all clues in current round are RESOLVED
   d. If yes and round is JEOPARDY or DOUBLE_JEOPARDY:
      - Backend should transition to next round or FINAL_PENDING
      - Redux polling will detect state change on next poll
      - Redux store updates with new state
      - All components reading from Redux automatically update UI

2. State transition detection (in Redux):
   a. Redux reducer compares previous game.state with current game.state
   b. If state changed:
      - Reducer automatically dispatches setSelectedClue(null) to clear modal
      - fetchGameData thunk refreshes board data in Redux store
      - All components subscribed to Redux state automatically update
      - UI reflects new state immediately
```

### 5. State Synchronization

**Problem**: Local state may drift from backend state, especially during rapid interactions.

**Solution**:
- Always fetch fresh state from backend after actions
- Use backend response as source of truth
- Never derive state locally
- Clear local UI state (like selectedClue) when backend indicates different state

**Algorithm**:
```
1. After any action (answer clue, submit wager, etc.):
   a. Redux thunk waits for backend response
   b. Thunk extracts updated state from response
   c. Thunk dispatches fetchGameData to get full game and board state
   d. fetchGameData thunk updates Redux store with backend response
   e. All components subscribed to Redux state automatically re-render
   f. Thunk clears any temporary UI state (e.g., selectedClue) if needed

2. State consistency checks (in Redux thunk or reducer):
   a. After fetchGameData updates Redux store:
      - Redux reducer checks if selectedClue exists but clue is RESOLVED
      - Reducer automatically clears selectedClue if inconsistent
   b. If game state changed (e.g., ACTIVE → FINAL_PENDING):
      - Redux reducer detects state change
      - Reducer clears selectedClue via setSelectedClue(null)
      - All components reading from Redux automatically update
      - UI reflects new game state immediately
```

## Implementation Details

### Redux as Single Source of Truth

**Key Principle**: Redux store is the single source of truth for all game state. All components read from Redux selectors and dispatch Redux actions/thunks. Polling updates the Redux store directly, causing all subscribed components to automatically re-render. No local component state is used for game data - everything flows through Redux.

**Benefits**:
- Centralized state management
- Automatic UI updates when state changes
- Predictable state flow
- Easy debugging with Redux DevTools
- No prop drilling
- Components automatically stay in sync

### Game Slice (gameSlice.ts)

Redux slice manages all game state and actions:

```typescript
// frontend/src/store/gameSlice.ts

State Shape:
{
  gameId: string | null;
  game: GameResponse | null;
  board: BoardResponse | null;
  selectedClue: {
    clueId: string;
    gameClueId: string;
    question: string;
    answer?: string;
    isDailyDouble: boolean;
    state: string;
    maxWager?: number;
  } | null;
  actionLoading: boolean;
  error: string | null;
  isPolling: boolean;
  pollingIntervalId: NodeJS.Timeout | null;
}

Actions:
- setGame(game: GameResponse | null)
- setBoard(board: BoardResponse | null)
- setSelectedClue(clue: SelectedClue | null)
- setActionLoading(loading: boolean)
- setError(error: string | null)
- setPolling(isPolling: boolean)
- setPollingIntervalId(id: NodeJS.Timeout | null)

Thunks:
- fetchGameData(gameId: string): AsyncThunk
  - Fetches game and board data from API
  - Updates Redux store with fresh state
  - Handles errors and updates error state
  
- startGame(gameId: string): AsyncThunk
  - Calls startGame API
  - Dispatches fetchGameData to refresh state
  
- selectClue(clueId: string, gameClueId: string): AsyncThunk
  - Fetches full game data if question missing
  - Calculates maxWager for Daily Double
  - Dispatches setSelectedClue with complete data
  
- answerClue(gameId: string, clueId: string, correct: boolean): AsyncThunk
  - Sets actionLoading to true
  - Calls answerClue API
  - Dispatches fetchGameData to refresh
  - Clears selectedClue
  - Sets actionLoading to false
  
- submitClueWager(gameId: string, clueId: string, wager: number): AsyncThunk
  - Sets actionLoading to true
  - Calls submitClueWager API
  - Dispatches fetchGameData to refresh
  - Updates selectedClue state to ANSWERED
  - Sets actionLoading to false
  
- submitFinalJeopardyWager(gameId: string, wager: number): AsyncThunk
  - Sets actionLoading to true
  - Calls submitFinalJeopardyWager API
  - Dispatches fetchGameData to refresh
  - Sets actionLoading to false
  
- answerFinalJeopardy(gameId: string, correct: boolean): AsyncThunk
  - Sets actionLoading to true
  - Calls answerFinalJeopardy API
  - Dispatches fetchGameData to refresh
  - Sets actionLoading to false
  
- startPolling(gameId: string): AsyncThunk
  - Checks if game state requires polling
  - Sets up polling interval
  - Stores interval ID in Redux state
  - Polling dispatches fetchGameData every 2-3 seconds
  
- stopPolling(): Action
  - Clears polling interval
  - Sets isPolling to false
  - Clears pollingIntervalId
```

**Polling Logic**:
- Implemented in Redux thunk (startPolling)
- Poll interval: 2-3 seconds
- Only poll when game state is ACTIVE, FINAL_PENDING, or FINAL_ACTIVE
- Polling automatically pauses when actionLoading is true (checked in thunk)
- Polling stops on component unmount (dispatch stopPolling)
- Polling stops when game reaches terminal state (reducer detects state change)
- All polling state managed in Redux store

**State Updates**:
- All state updates go through Redux actions/thunks
- Components subscribe to Redux state via selectors
- UI automatically re-renders when Redux state changes
- No local state for game data - Redux is single source of truth

## Edge Cases to Handle

1. **Network Interruption**: 
   - Show error message
   - Allow manual refresh
   - Resume polling when connection restored

2. **Concurrent Actions**:
   - Components check Redux actionLoading state before dispatching actions
   - Redux thunks check actionLoading and return early if action in progress
   - UI buttons disabled when actionLoading is true (read from Redux)

3. **State Desynchronization**:
   - Redux thunks always fetch fresh state after actions
   - Redux store is single source of truth (backend is authoritative source)
   - Components never maintain local game state - all from Redux
   - Redux state always reflects latest backend response

4. **Round Completion**:
   - Detect when all clues are RESOLVED
   - Automatically refresh to get new round state
   - Handle transition to Final Jeopardy

5. **Game Completion**:
   - Stop polling when game is COMPLETED or ELIMINATED
   - Show final score and summary
   - Disable all actions

6. **Invalid Clue Selection**:
   - If clue is already RESOLVED, show read-only view
   - If clue state doesn't match backend, refresh and update
