Implement REST API endpoints that expose the game domain services through HTTP interfaces. All endpoints must enforce authentication, authorization, input validation, state enforcement, and structured error handling. Endpoints remain thin, delegating all business logic to domain services. This supports Phase 6 of the implementation roadmap.

Get detailed information about a specific game.

#### POST /games/:id/start

#### GET /games/:id/board

#### POST /games/:id/clues/:clueId/answer

#### POST /games/:id/final-jeopardy/wager
Submit a wager for Final Jeopardy.

#### POST /games/:id/final-jeopardy/answer
Submit the answer (correct/incorrect) for Final Jeopardy.

## Detailed API Specifications

### 1. POST /games

**Description**: Create a new game for the authenticated user.

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only create games for themselves (userId from JWT)

**Request**:
- Method: `POST`
- Path: `/games`
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)
  - `Content-Type: application/json`
- Body: Empty (no request body required)

**Response**:
- Status: `201 Created` (success)
- Body:
```typescript
{
  id: string;
  userId: string;
  state: 'PENDING' | 'ACTIVE' | 'FINAL_PENDING' | 'FINAL_ACTIVE' | 'ELIMINATED' | 'COMPLETED';
  score: number;
  createdAt: string; // ISO 8601 date string
  updatedAt: string; // ISO 8601 date string
  finalJeopardy: {
    id: string;
    gameId: string;
    clueId: string;
    wager: number;
    correct: boolean | null;
    scoreDelta: number | null;
    answeredAt: string | null; // ISO 8601 date string
    clue: {
      id: string;
      category: string;
      round: 'FINAL';
      value: number;
      question: string;
      answer: string;
      dailyDouble: boolean;
      createdAt: string; // ISO 8601 date string
    };
  };
}
```

**Error Responses**:
- `400 Bad Request`: Invalid request (e.g., user already has active game)
  ```json
  {
    "statusCode": 400,
    "message": "User already has an active game",
    "error": "Bad Request"
  }
  ```
- `401 Unauthorized`: Missing or invalid JWT token
  ```json
  {
    "statusCode": 401,
    "message": "Authorization token is required" | "Invalid or expired token",
    "error": "Unauthorized"
  }
  ```
- `500 Internal Server Error`: Database error or clue selection failure
  ```json
  {
    "statusCode": 500,
    "message": "No Final Jeopardy clues available in database" | "Failed to create game",
    "error": "Internal Server Error"
  }
  ```

**Business Rules**:
- User may only have one active game at a time
- Game is created with `PENDING` state
- Initial score is `0`
- Final Jeopardy clue is selected deterministically
- Game creation is atomic (transaction)

### 2. GET /games

**Description**: List all games for the authenticated user.

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only see their own games

**Request**:
- Method: `GET`
- Path: `/games`
- Query Parameters:
  - `status` (optional): Filter by game state (`PENDING`, `ACTIVE`, `FINAL_PENDING`, `FINAL_ACTIVE`, `ELIMINATED`, `COMPLETED`)
  - `limit` (optional): Maximum number of results (default: 50, max: 100)
  - `offset` (optional): Pagination offset (default: 0)
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)

**Response**:
- Status: `200 OK` (success)
- Body:
```typescript
{
  games: Array<{
    id: string;
    userId: string;
    state: GameState;
    score: number;
    createdAt: string;
    updatedAt: string;
  }>;
  total: number;
  limit: number;
  offset: number;
}
```

**Error Responses**:
- `401 Unauthorized`: Missing or invalid JWT token
- `400 Bad Request`: Invalid query parameters

### 4. POST /games/:id/start

**Description**: Start a game by creating Jeopardy and Double Jeopardy boards. Transitions game from `PENDING` to `ACTIVE` state.

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only start their own games

**Request**:
- Method: `POST`
- Path: `/games/:id/start`
- Path Parameters:
  - `id`: Game ID (required)
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)
- Body: Empty

**Response**:
- Status: `200 OK` (success)
- Body:
```typescript
{
  id: string;
  userId: string;
  state: 'ACTIVE';
  score: number;
  createdAt: string;
  updatedAt: string;
  message: "Game started successfully";
}
```

**Error Responses**:
- `400 Bad Request`: Invalid game state (not `PENDING`)
  ```json
  {
    "statusCode": 400,
    "message": "Game cannot be started. Current state: <state>",
    "error": "Bad Request"
  }
  ```
- `401 Unauthorized`: Missing or invalid JWT token
- `403 Forbidden`: User does not own this game
- `404 Not Found`: Game not found
- `500 Internal Server Error`: Failed to create boards (insufficient clues, etc.)
  ```json
  {
    "statusCode": 500,
    "message": "Failed to create game boards: <reason>",
    "error": "Internal Server Error"
  }
  ```

**Business Rules**:
- Game must be in `PENDING` state
- Creates 6 categories × 5 clues for Jeopardy round
- Creates 6 categories × 5 clues for Double Jeopardy round
- Jeopardy round must have exactly 1 Daily Double
- Double Jeopardy round must have exactly 2 Daily Doubles
- Transitions game state to `ACTIVE`
- All operations are atomic (transaction)

### 5. GET /games/:id/board

**Description**: Get the current round's board state (Jeopardy, Double Jeopardy, or Final Jeopardy).

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only access their own games

**Request**:
- Method: `GET`
- Path: `/games/:id/board`
- Path Parameters:
  - `id`: Game ID (required)
- Query Parameters:
  - `round` (optional): Specific round to retrieve (`JEOPARDY`, `DOUBLE_JEOPARDY`, `FINAL`). If omitted, returns current active round.
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)

**Response**:
- Status: `200 OK` (success)
- Body:
```typescript
{
  gameId: string;
  currentRound: 'JEOPARDY' | 'DOUBLE_JEOPARDY' | 'FINAL' | null;
  gameState: GameState;
  score: number;
  board: {
    round: 'JEOPARDY' | 'DOUBLE_JEOPARDY';
    categories: Array<{
      name: string;
      clues: Array<{
        gameClueId: string;
        clueId: string;
        value: number;
        state: 'UNANSWERED' | 'ANSWERED' | 'RESOLVED';
        dailyDouble: boolean;
        // Only include question/answer if clue is ANSWERED or RESOLVED
        question?: string;
        answer?: string;
        wager?: number;
        scoreDelta?: number;
      }>;
    }>;
  } | {
    round: 'FINAL';
    clue: {
      clueId: string;
      category: string;
      value: number;
      question: string; // Always visible for Final Jeopardy
      answer: string; // Only visible if answered
      wager: number;
      correct: boolean | null;
      scoreDelta: number | null;
      answeredAt: string | null;
    };
  } | null;
}
```

**Error Responses**:
- `401 Unauthorized`: Missing or invalid JWT token
- `403 Forbidden`: User does not own this game
- `404 Not Found`: Game not found
- `400 Bad Request`: Invalid round parameter or game state

**Business Rules**:
- For Jeopardy/Double Jeopardy: Only show question/answer if clue is `ANSWERED` or `RESOLVED`
- For Final Jeopardy: Always show question, only show answer if answered
- Board structure depends on current game state

### 6. POST /games/:id/clues/:clueId/answer

**Description**: Answer a regular clue or submit Daily Double answer adjudication.

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only answer clues in their own games

**Request**:
- Method: `POST`
- Path: `/games/:id/clues/:clueId/answer`
- Path Parameters:
  - `id`: Game ID (required)
  - `clueId`: GameClue ID (required)
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)
- Body:
```typescript
{
  correct: boolean; // Required: true if player answered correctly, false otherwise
}
```

**Response**:
- Status: `200 OK` (success)
- Body:
```typescript
{
  gameClueId: string;
  clueId: string;
  state: 'RESOLVED';
  correct: boolean;
  scoreDelta: number;
  newScore: number;
  answeredAt: string;
  message: "Clue answered successfully";
}
```

**Error Responses**:
- `400 Bad Request`: 
  - Invalid game state
  - Clue already answered
  - Missing or invalid `correct` field
  ```json
  {
    "statusCode": 400,
    "message": "Clue has already been answered" | "Game is not in an active state" | "Invalid request body",
    "error": "Bad Request"
  }
  ```
- `401 Unauthorized`: Missing or invalid JWT token
- `403 Forbidden`: User does not own this game
- `404 Not Found`: Game or clue not found
  ```json
  {
    "statusCode": 404,
    "message": "Game not found" | "Clue not found in this game",
    "error": "Not Found"
  }
  ```

**Business Rules**:
- Game must be in `ACTIVE` state
- Clue must be in `UNANSWERED` or `ANSWERED` state
- For Daily Doubles: Wager must be submitted first (clue in `ANSWERED` state)
- Score is updated based on correctness and clue value (or wager for Daily Doubles)
- Clue state transitions to `RESOLVED`
- Game state may transition to `FINAL_PENDING` if all clues are resolved
- All operations are atomic (transaction)

### 7. POST /games/:id/clues/:clueId/wager

**Description**: Submit a wager for a Daily Double clue.

**Authentication**: Required (JWT token in Authorization header)

**Authorization**: User can only wager on clues in their own games

**Request**:
- Method: `POST`
- Path: `/games/:id/clues/:clueId/wager`
- Path Parameters:
  - `id`: Game ID (required)
  - `clueId`: GameClue ID (required)
- Headers:
  - `Authorization: Bearer <jwt-token>` (required)
- Body:
```typescript
{
  wager: number; // Required: wager amount in dollars (minimum $5)
}
```

**Response**:
- Status: `200 OK` (success)
- Body:
```typescript
{
  gameClueId: string;
  clueId: string;
  wager: number;
  currentScore: number;
  maxWager: number;
  message: "Wager submitted successfully";
}
```

**Error Responses**:
- `400 Bad Request`:
  - Invalid wager amount (below minimum or above maximum)
  - Clue is not a Daily Double
  - Clue already has a wager
  - Invalid game state
  ```json
  {
    "statusCode": 400,
    "message": "Wager must be at least $5" | "Wager exceeds maximum allowed" | "This clue is not a Daily Double" | "Wager has already been submitted",
    "error": "Bad Request"
  }
  ```
- `401 Unauthorized`: Missing or invalid JWT token
- `403 Forbidden`: User does not own this game
- `404 Not Found`: Game or clue not found

**Business Rules**:
- Game must be in `ACTIVE` state
- Clue must be a Daily Double
- Clue must be in `UNANSWERED` state
- Minimum wager: $5
- Maximum wager: greater of (current score, highest clue value in round)
- If score ≤ $0, max wager = highest clue value in round
- Clue state transitions to `ANSWERED` (not yet resolved)
- Wager is stored in `GameClue.wager`

## Input Validation

### Validation Rules

1. **Wager Validation**:
   - Must be a number
   - Must be non-negative
   - Must meet minimum requirements ($5 for Daily Doubles)
   - Must not exceed maximum (current score or round max value)

2. **Answer Validation**:
   - `correct` field must be a boolean
   - Must not be null or undefined

3. **Game ID Validation**:
   - Must be a valid UUID/cuid format
   - Must exist in database
   - Must belong to requesting user

4. **Clue ID Validation**:
   - Must be a valid UUID/cuid format
   - Must exist in the game
   - Must be in correct state for operation

### Validation Implementation

Use NestJS class-validator decorators:
- `@IsBoolean()`, `@IsNumber()`, `@IsNotEmpty()`, `@Min()`, `@Max()`
- Global validation pipe configured in `main.ts`

## Authorization Checks

### Ownership Verification

All endpoints must verify:
1. Game exists
2. Game belongs to the authenticated user (userId from JWT matches game.userId)

**Implementation Pattern**:
```typescript
// In controller or service
const game = await this.gameService.getGameById(gameId);
if (!game) {
  throw new GameNotFoundException(gameId);
}
if (game.userId !== user.userId) {
  throw new UnauthorizedGameAccessException();
}
```

## State Enforcement

### Game State Transitions

Controllers must enforce valid state transitions:

1. **PENDING** → **ACTIVE**: Via `POST /games/:id/start`
2. **ACTIVE** → **FINAL_PENDING**: Automatically when all clues resolved
3. **FINAL_PENDING** → **FINAL_ACTIVE**: Via `POST /games/:id/final-jeopardy/wager`
4. **FINAL_ACTIVE** → **COMPLETED**: Via `POST /games/:id/final-jeopardy/answer`
5. **ACTIVE** → **ELIMINATED**: Automatically if score ≤ $0 after Double Jeopardy

### Clue State Transitions

1. **UNANSWERED** → **ANSWERED**: Via `POST /games/:id/clues/:clueId/wager` (Daily Doubles only)
2. **UNANSWERED/ANSWERED** → **RESOLVED**: Via `POST /games/:id/clues/:clueId/answer`

## Error Response Format

All error responses follow NestJS standard format:

```typescript
{
  statusCode: number;
  message: string | string[];
  error: string;
}
```

### Standard HTTP Status Codes

- `200 OK`: Successful GET, PUT, PATCH
- `201 Created`: Successful POST (creation)
- `400 Bad Request`: Validation errors, invalid state
- `401 Unauthorized`: Missing or invalid authentication
- `403 Forbidden`: Authorization failure (wrong user)
- `404 Not Found`: Resource not found
- `500 Internal Server Error`: Server errors, database failures

## Performance Considerations

1. **Query Optimization**:
   - Use Prisma `include` selectively
   - Avoid N+1 queries
   - Use indexes for game lookups

2. **Response Size**:
   - Board responses may be large (30 clues × details)
   - Consider pagination for game lists
   - Consider lazy loading for clue details

3. **Caching** (Future):
   - Consider caching active game state
   - Cache board structures

## Security Considerations

1. **Authentication**:
   - All endpoints require JWT authentication
   - Use `@UseGuards(AuthGuard)` on controller

2. **Authorization**:
   - Verify ownership on every request
   - Never trust client-provided userId

3. **Input Validation**:
   - Validate all inputs
   - Sanitize user-provided data
   - Prevent SQL injection (Prisma handles this)

4. **Error Messages**:
   - Don't expose internal details
   - Don't reveal existence of other users' games

---

## Constraints

1. **Thin Controllers**:
   - Controllers only handle HTTP concerns
   - All business logic in services
   - No duplicate rule enforcement

2. **State Authority**:
   - Backend is authoritative for all state
   - Client cannot override state transitions
   - All mutations are validated

3. **Immutability**:
   - Completed games are read-only
   - Resolved clues cannot be modified
   - Historical records are immutable
