# Final Jeopardy File Parsing Plan

## Description

Implement a parsing service to process raw Jeopardy clue TSV files from Seasons 33-41, filter for Final Jeopardy clues (round = 3), validate required fields, and output cleaned data to a parsed directory. This supports Phase 3 of the implementation roadmap by preparing Final Jeopardy clues for database ingestion.

## Files to Create

- `backend/src/data/parsing/final-jeopardy-parser.service.ts` - Main parsing service
- `backend/src/data/parsing/final-jeopardy-parser.service.spec.ts` - Unit tests
- `backend/src/data/parsing/types.ts` - TypeScript interfaces for parsed data
- `backend/src/data/parsing/index.ts` - Export barrel file

## Files to Modify

- `backend/src/app.module.ts` - Register parsing service if needed as a provider
- `backend/package.json` - Add any required dependencies (e.g., CSV/TSV parser library)

## Data Structure

### Input Files
- Location: `backend/data/jeopardy_clue_dataset/raw/`
- Format: TSV (tab-separated values)
- Files: `season33.tsv`, `season34.tsv`, `season35.tsv`, `season36.tsv`, `season37.tsv`, `season38.tsv`, `season39.tsv`, `season40.tsv`, `season41.tsv`
- Columns (in order):
  - `round` - Integer (1=Jeopardy, 2=Double Jeopardy, 3=Final Jeopardy)
  - `clue_value` - Integer (dollar value, 0 for Final Jeopardy)
  - `daily_double_value` - Integer (0 for Final Jeopardy)
  - `category` - String (category name)
  - `comments` - String (often empty)
  - `answer` - String (correct response)
  - `question` - String (clue text)
  - `air_date` - String (YYYY-MM-DD format)
  - `notes` - String (often empty)

### Output Format
- Location: `backend/data/jeopardy_clue_dataset/parsed/`
- Format: JSON (one file per season, or single consolidated file)
- Structure: Array of parsed clue objects

## Algorithm

### Step 1: File Discovery
1. Read directory `backend/data/jeopardy_clue_dataset/raw/`
2. Filter for files matching pattern `season{33-41}.tsv`
3. Process files in ascending season order (33 → 41)

### Step 2: TSV Parsing
1. Read each TSV file line by line
2. Skip header row (first line)
3. Split each line by tab character (`\t`)
4. Map columns to named fields based on column order:
   - Column 0: `round`
   - Column 1: `clue_value`
   - Column 2: `daily_double_value`
   - Column 3: `category`
   - Column 4: `comments`
   - Column 5: `answer`
   - Column 6: `question`
   - Column 7: `air_date`
   - Column 8: `notes`

### Step 3: Filtering
1. Filter rows where `round` column equals `3` (Final Jeopardy)
2. Discard all other rows

### Step 4: Validation
For each filtered row, validate:
- `category`: Must be non-empty string (after trimming whitespace)
- `answer`: Must be non-empty string (after trimming whitespace)
- `question`: Must be non-empty string (after trimming whitespace)

If any validation fails:
- Log the row with file name, line number, and validation error
- Skip the row (do not include in output)
- Continue processing remaining rows

### Step 5: Data Normalization
For each valid row:
1. Trim whitespace from `category`, `answer`, and `question`
2. Extract `season_number` from filename (e.g., `season33.tsv` → `33`)
3. Create normalized object:
   ```typescript
   {
     seasonNumber: number,
     category: string,
     answer: string,
     question: string,
     airDate: string, // Optional, preserve if available
     sourceFile: string // Original filename for traceability
   }
   ```

### Step 6: Deduplication (Optional)
- Track seen clues by a composite key (category + question + answer)
- Skip exact duplicates within the same processing run
- Log duplicate occurrences

### Step 7: Output
1. Write parsed data to `backend/data/jeopardy_clue_dataset/parsed/`
2. Output format options:
   - Option A: Single consolidated file `final-jeopardy-clues.json` with all seasons
   - Option B: One file per season: `season33-final.json`, `season34-final.json`, etc.
3. Include metadata in output:
   - Total clues parsed
   - Total clues after validation
   - Total duplicates skipped (if deduplication enabled)
   - Processing timestamp

### Step 8: Logging
Log the following:
- Files processed (count and names)
- Total rows read
- Rows filtered (Final Jeopardy count)
- Rows validated successfully
- Rows rejected (with reason: missing category/answer/question)
- Duplicates found (if deduplication enabled)
- Output file location and record count

## Validation Rules

### Required Fields (Non-Empty After Trimming)
- `category`: Must have at least one non-whitespace character
- `answer`: Must have at least one non-whitespace character  
- `question`: Must have at least one non-whitespace character

### Rejection Criteria
A row is rejected if:
- `round` is not `3` (handled by filtering, not validation)
- `category` is empty or only whitespace
- `answer` is empty or only whitespace
- `question` is empty or only whitespace

## Error Handling

- File read errors: Log error, skip file, continue with next file
- Malformed TSV (wrong column count): Log line number and file, skip row, continue
- Missing files: Log warning, continue with available files
- Output write errors: Log error, fail processing with clear error message
