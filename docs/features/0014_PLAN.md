# Clue Display, Answer Submission, and Scoring

## Description

Implement the core gameplay interaction where a player can click a clue on the game board, view the clue details, submit an answer, and have the game state update accordingly. This includes frontend UI for displaying selected clues, backend API for processing answers, score calculation, and game state progression.

## Implementation Algorithm

### Phase 1: Backend Service Implementation

1. **Implement `answerClue()` in GameService**
   - Find GameClue by ID using `prisma.gameClue.findUnique()` with `include: { clue: true, game: true }`
   - Validate GameClue exists
   - Validate GameClue belongs to the game (`gameClue.gameId === gameId`)
   - Validate game state is ACTIVE
   - Validate GameClue state is UNANSWERED (throw error if already RESOLVED)
   - Calculate score delta:
     - If correct: `scoreDelta = clue.value` (positive)
     - If incorrect: `scoreDelta = -clue.value` (negative)
     - For Daily Doubles: use wager amount instead of clue value if wager exists
   - Update game score: `newScore = game.score + scoreDelta`
   - Update GameClue in transaction:
     - Set `state = ClueState.RESOLVED`
     - Set `scoreDelta = calculated scoreDelta`
     - Set `answeredAt = new Date()`
   - Update Game score in same transaction
   - Check if all GameClues for both Jeopardy and Double Jeopardy rounds are resolved:
     - Query all GameClues for the game where `clue.round = JEOPARDY`
     - Query all GameClues for the game where `clue.round = DOUBLE_JEOPARDY`
     - If all clues in BOTH rounds have `state = RESOLVED`, transition game to `FINAL_PENDING`
     - Note: Final Jeopardy can only begin after both Jeopardy and Double Jeopardy rounds are complete
   - Return updated GameClue and new score

2. **Error Handling**
   - Throw `ClueNotFoundException` if GameClue not found
   - Throw `GameStateException` if game not ACTIVE
   - Throw error if GameClue already RESOLVED
   - Throw error if GameClue doesn't belong to game

## API Contract

### Request
- **Endpoint**: `POST /games/:gameId/clues/:clueId/answer`
- **Auth**: Required (AuthGuard)
- **Body**: 
  ```typescript
  {
    correct: boolean  // Whether the player's answer was correct
  }
  ```
- **Path Parameters**:
  - `gameId: string` - Game ID
  - `clueId: string` - GameClue ID (not Clue ID)

### Response
- **Success (200)**:
  ```typescript
  {
    gameClueId: string;
    clueId: string;
    state: 'RESOLVED';
    correct: boolean;
    scoreDelta: number;  // Positive if correct, negative if incorrect
    newScore: number;    // Updated game score
    answeredAt: string; // ISO timestamp
    message: string;
  }
  ```

### Error Responses
- **404**: Game or GameClue not found
- **403**: Unauthorized access to game
- **400**: Game not in ACTIVE state, or clue already resolved
- **500**: Server error

## Data Flow

1. **User clicks clue on board**
   - `GameBoard` component calls `onClueClick(clueId, gameClueId)`
   - `GameDetailPage` dispatches `selectClue({ clueId, gameClueId })`
   - Redux state updates with selected clue
   - ClueModal opens

2. **User views clue and submits answer**
   - ClueModal displays question
   - User clicks "Show Answer" (optional)
   - Answer is revealed
   - User clicks "I got it right" or "I got it wrong"
   - ClueModal calls `onSubmit(correct)`
   - `GameDetailPage` dispatches `answerClue({ gameId, clueId, correct })`

3. **Backend processes answer**
   - Controller validates request
   - Service finds GameClue and validates state
   - Service calculates score delta
   - Service updates GameClue and Game in transaction
   - Service checks if round is complete, transitions to FINAL_PENDING if so
   - Service returns updated GameClue and new score

4. **Frontend updates state**
   - `answerClue` thunk receives response
   - Thunk dispatches `fetchGameData` to refresh game state
   - Board re-renders with updated clue states
   - Score display updates
   - ClueModal shows result then closes
   - Selected clue is cleared

## Game Progression Rules

1. **Clue Resolution**
   - Only UNANSWERED clues can be answered
   - Once answered, clue state becomes RESOLVED
   - RESOLVED clues cannot be answered again

2. **Score Calculation**
   - Correct answer: `scoreDelta = +clue.value`
   - Incorrect answer: `scoreDelta = -clue.value`
   - Daily Doubles: Use wager amount instead of clue value (if wager exists)
   - Scores may be positive or negative (no minimum enforced)

3. **Round Completion**
   - After each clue is resolved, check if all clues in both Jeopardy and Double Jeopardy rounds are resolved
   - Query all GameClues for both rounds and check if all have `state = RESOLVED`
   - If all clues in BOTH rounds are RESOLVED:
     - Transition game state from ACTIVE to FINAL_PENDING
     - This allows Final Jeopardy to begin
   - Note: Final Jeopardy can only begin after both Jeopardy and Double Jeopardy rounds are complete

4. **State Transitions**
   - ACTIVE → FINAL_PENDING: When all clues in both Jeopardy and Double Jeopardy rounds are resolved
   - Game must be ACTIVE to answer clues
   - Cannot answer clues when game is not ACTIVE

## Error Cases

### Backend Errors
1. **GameClue not found**
   - Return 404 with ClueNotFoundException
   - Frontend shows error message

2. **GameClue already resolved**
   - Return 400 with error message
   - Frontend shows error and prevents submission

3. **Game not in ACTIVE state**
   - Return 400 with GameStateException
   - Frontend shows error message

4. **GameClue doesn't belong to game**
   - Return 400 with error message
   - Frontend shows error

5. **Database transaction failure**
   - Return 500 with error message
   - Frontend shows error, state remains unchanged

### Frontend Errors
1. **Network error during submission**
   - Show error message
   - Keep modal open, allow retry

2. **Invalid clue selection**
   - If clue is already RESOLVED, disable click or show message
   - Prevent opening modal for resolved clues

3. **State desync**
   - After submission, always refresh from backend
   - Use polling or manual refresh to sync state

## State Management Details

### Redux State
- `selectedClue: SelectedClue | null` - Currently selected clue
- `game: GameResponse | null` - Full game data
- `board: BoardResponse | null` - Current board state
- `actionLoading: boolean` - Whether an action is in progress
- `error: string | null` - Error message if any

### Component State (ClueModal)
- `showAnswer: boolean` - Whether to show the answer
- `submitting: boolean` - Whether answer is being submitted
- `result: { correct: boolean, scoreDelta: number, newScore: number } | null` - Result after submission

## Validation Rules

### Backend Validations
1. Game must exist and belong to user
2. Game must be in ACTIVE state
3. GameClue must exist
4. GameClue must belong to the game
5. GameClue must be in UNANSWERED or ANSWERED state (not RESOLVED)
6. Score delta calculation must be correct
7. Scores may be negative (no minimum enforced)

### Frontend Validations
1. Clue must be UNANSWERED to be clickable
2. Modal should not open for RESOLVED clues
3. Answer submission should be disabled while submitting
4. Should prevent multiple simultaneous submissions

## Daily Double Handling

- For this feature, Daily Doubles are treated as regular clues
- Wager submission is out of scope (handled separately)
- If a Daily Double has a wager set, use wager amount for score calculation instead of clue value
- If no wager is set, use clue value (fallback behavior)
