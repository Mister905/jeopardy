# User Profile (Username) and Historical Player Statistics Dashboard

## Description

Extend the user domain to include a configurable username (set during signup) and persistent historical gameplay statistics that are automatically updated as games are completed. Statistics are stored incrementally on the User model and displayed on a dedicated dashboard route accessible from the base URL. Only completed games contribute to statistics, and stats are updated transactionally when game events occur (clue resolution, Daily Double wagers, Final Jeopardy completion).

## Schema Changes

### Prisma Schema (`backend/prisma/schema.prisma`)

**Modify User model:**
- Add `username String` field (required, non-unique)
- Add statistics fields directly on User model (incremental approach):
  - `totalGamesPlayed Int @default(0)` - Count of COMPLETED games only
  - `averageScore Float @default(0)` - Average of final scores from completed games
  - `bestScore Int?` - Highest final score achieved
  - `worstScore Int?` - Lowest final score achieved (can be negative)
  - `totalWinnings Int @default(0)` - Sum of all positive final scores
  - `totalCorrectAnswers Int @default(0)` - Count of correct answers across all rounds
  - `totalIncorrectAnswers Int @default(0)` - Count of incorrect answers across all rounds
  - `jeopardyCorrect Int @default(0)` - Correct answers in Jeopardy round
  - `jeopardyIncorrect Int @default(0)` - Incorrect answers in Jeopardy round
  - `doubleJeopardyCorrect Int @default(0)` - Correct answers in Double Jeopardy round
  - `doubleJeopardyIncorrect Int @default(0)` - Incorrect answers in Double Jeopardy round
  - `finalJeopardyCorrect Int @default(0)` - Correct Final Jeopardy answers
  - `finalJeopardyIncorrect Int @default(0)` - Incorrect Final Jeopardy answers
  - `dailyDoubleCorrect Int @default(0)` - Correct Daily Double answers
  - `dailyDoubleIncorrect Int @default(0)` - Incorrect Daily Double answers
  - `currentCorrectStreak Int @default(0)` - Current consecutive correct answers
  - `longestCorrectStreak Int @default(0)` - Career longest correct streak
  - `currentIncorrectStreak Int @default(0)` - Current consecutive incorrect answers
  - `longestIncorrectStreak Int @default(0)` - Career longest incorrect streak
  - `largestSuccessfulDailyDoubleWager Int?` - Largest successful Daily Double wager
  - `largestSuccessfulFinalJeopardyWager Int?` - Largest successful Final Jeopardy wager
  - `largestUnsuccessfulDailyDoubleWager Int?` - Largest unsuccessful Daily Double wager
  - `largestUnsuccessfulFinalJeopardyWager Int?` - Largest unsuccessful Final Jeopardy wager

**Migration considerations:**
- Username field requires migration with default value handling for existing users
- All stat fields default to 0 or null (nullable for optional stats)
- Migration must handle existing users by setting username to email (or requiring manual update)

## Implementation Algorithm

### Phase 1: Schema and Data Layer

1. **Create Prisma Migration**
   - Add `username` field to User model (required, non-unique)
   - Add all statistics fields with appropriate defaults
   - Handle existing users: set username to email for existing records (or require manual update)
   - Run migration: `npx prisma migrate dev --name add_user_profile_and_stats`

2. **Create User Service**
   - Implement `ensureUserExists()`: 
     - Check if User exists by userId
     - If not, create User with email and username
     - Use upsert pattern: `prisma.user.upsert({ where: { id: userId }, update: {}, create: { id, email, username } })`
   - Implement stat update methods with transactional updates
   - All stat updates use Prisma's atomic increment operations where possible

3. **Stat Update Logic - Clue Resolution**
   - `updateUserStatsOnClueResolved()`:
     - Determine round from `gameClue.clue.round`
     - If correct: increment `totalCorrectAnswers` and round-specific correct counter
     - If incorrect: increment `totalIncorrectAnswers` and round-specific incorrect counter
     - Update streak metrics (see streak algorithm below)
     - Use `prisma.user.update({ where: { id }, data: { totalCorrectAnswers: { increment: 1 } } })` for atomic updates

4. **Stat Update Logic - Daily Double Wager**
   - `updateUserStatsOnDailyDoubleWager()`:
     - Called when Daily Double is answered (after wager was submitted)
     - If correct: update `largestSuccessfulDailyDoubleWager` if wager > current max
     - If incorrect: update `largestUnsuccessfulDailyDoubleWager` if wager > current max
     - Also update Daily Double correct/incorrect counters (handled by clue resolution)

5. **Stat Update Logic - Final Jeopardy Wager**
   - `updateUserStatsOnFinalJeopardyWager()`:
     - Called when Final Jeopardy is answered
     - If correct: update `largestSuccessfulFinalJeopardyWager` if wager > current max
     - If incorrect: update `largestUnsuccessfulFinalJeopardyWager` if wager > current max
     - Update Final Jeopardy correct/incorrect counters

6. **Stat Update Logic - Game Completion**
   - `updateUserStatsOnGameComplete()`:
     - Called when game transitions to COMPLETED state
     - Increment `totalGamesPlayed`
     - Update `averageScore`: `(currentAverage * (totalGames - 1) + finalScore) / totalGames`
     - Update `bestScore`: `Math.max(currentBest, finalScore)` (handle null)
     - Update `worstScore`: `Math.min(currentWorst, finalScore)` (handle null)
     - Update `totalWinnings`: add finalScore if positive, otherwise no change
     - All updates in single transaction

7. **Streak Algorithm**
   - When clue is answered correctly:
     - Increment `currentCorrectStreak`
     - Reset `currentIncorrectStreak` to 0
     - Update `longestCorrectStreak` if `currentCorrectStreak > longestCorrectStreak`
   - When clue is answered incorrectly:
     - Increment `currentIncorrectStreak`
     - Reset `currentCorrectStreak` to 0
     - Update `longestIncorrectStreak` if `currentIncorrectStreak > longestIncorrectStreak`
   - Streaks are career-level and persist across games

### Phase 2: Backend API Integration

1. **Modify Game Service - User Creation**
   - In `createGame()`:
     - Before creating game, call `userService.ensureUserExists(userId, email, username)`
     - Username must be passed from frontend (requires signup endpoint modification)
     - If User doesn't exist, create with provided username
     - If User exists but username is missing, throw error (username required)

2. **Modify Game Service - Stat Updates on Clue Resolution**
   - In `answerClue()`:
     - After successfully updating GameClue and Game score
     - Call `userService.updateUserStatsOnClueResolved(userId, updatedGameClue, correct, gameClue.clue.round)`
     - Pass correct boolean and round enum
     - Handle errors gracefully (log but don't fail game operation)

3. **Modify Game Service - Stat Updates on Daily Double**
   - In `answerClue()` when `isDailyDouble` is true:
     - After clue resolution
     - Call `userService.updateUserStatsOnDailyDoubleWager(userId, gameClue.wager!, correct)`
     - Only if wager exists and clue is Daily Double

4. **Modify Game Service - Stat Updates on Final Jeopardy**
   - In `answerFinalJeopardy()`:
     - After Final Jeopardy is answered and game is marked COMPLETED
     - Call `userService.updateUserStatsOnFinalJeopardyWager(userId, finalJeopardy.wager, correct)`
     - Call `userService.updateUserStatsOnGameComplete(userId, finalScore)`
   - Both calls in same transaction as game completion

5. **Create User Controller**
   - `GET /me/dashboard` endpoint:
     - Uses `@CurrentUser()` to get authenticated user
     - Calls `userService.getUserProfile(userId)`
     - Returns `UserProfileResponseDto` with computed accuracy percentages

6. **User Profile Response Calculation**
   - `getUserProfile()`:
     - Fetch User with all stat fields
     - Compute accuracy percentages:
       - `overallAccuracy = (totalCorrectAnswers / (totalCorrectAnswers + totalIncorrectAnswers)) * 100`
       - `jeopardyAccuracy = (jeopardyCorrect / (jeopardyCorrect + jeopardyIncorrect)) * 100`
       - `doubleJeopardyAccuracy = (doubleJeopardyCorrect / (doubleJeopardyCorrect + doubleJeopardyIncorrect)) * 100`
       - `finalJeopardyAccuracy = (finalJeopardyCorrect / (finalJeopardyCorrect + finalJeopardyIncorrect)) * 100`
       - `dailyDoubleAccuracy = (dailyDoubleCorrect / (dailyDoubleCorrect + dailyDoubleIncorrect)) * 100`
     - Handle division by zero: return 0 or null if denominator is 0
     - Return username and all stats in frontend-friendly format

## Data Flow

### User Creation Flow
1. User signs up via frontend with email, password, and username
2. Frontend calls Supabase signup (creates auth user)
3. Frontend calls backend to create User record (or backend creates on first game)
4. Backend `ensureUserExists()` creates User with email and username
5. User record is persisted with initial stat values (all zeros)

### Stat Update Flow - Clue Resolution
1. User answers clue (correct or incorrect)
2. `answerClue()` in GameService updates GameClue and Game score
3. `answerClue()` calls `userService.updateUserStatsOnClueResolved()`
4. UserService atomically increments correct/incorrect counters based on round
5. UserService updates streak metrics
6. Stat update happens in same transaction as game update (or immediately after)

### Stat Update Flow - Game Completion
1. User completes Final Jeopardy
2. `answerFinalJeopardy()` marks game as COMPLETED
3. `answerFinalJeopardy()` calls `userService.updateUserStatsOnFinalJeopardyWager()`
4. `answerFinalJeopardy()` calls `userService.updateUserStatsOnGameComplete()`
5. UserService updates game count, averages, best/worst scores, total winnings
6. All updates in single transaction

### Dashboard Display Flow
1. User navigates to `/dashboard`
2. Frontend calls `GET /me/dashboard`
3. Backend fetches User record with all stat fields
4. Backend computes accuracy percentages
5. Backend returns formatted response
6. Frontend displays stats grouped by category

## Event-Driven Stat Update Logic

### When Clue is Resolved (`answerClue`)
- Update round-specific correct/incorrect counters
- Update overall correct/incorrect counters
- Update streak metrics (current and longest)
- If Daily Double: also update Daily Double wager stats (if applicable)

### When Daily Double Wager is Resolved
- Update `largestSuccessfulDailyDoubleWager` or `largestUnsuccessfulDailyDoubleWager`
- Daily Double correct/incorrect already handled by clue resolution

### When Final Jeopardy is Answered
- Update `largestSuccessfulFinalJeopardyWager` or `largestUnsuccessfulFinalJeopardyWager`
- Update Final Jeopardy correct/incorrect counters
- Trigger game completion stats update

### When Game Completes
- Increment `totalGamesPlayed`
- Recalculate `averageScore` using incremental formula
- Update `bestScore` and `worstScore` if applicable
- Add to `totalWinnings` if final score is positive

## Transaction Safety

- All stat updates use Prisma transactions where multiple fields are updated
- Stat updates should not block game operations (catch errors, log, continue)
- Use atomic increment operations (`{ increment: 1 }`) where possible
- For calculated fields (averageScore), use transaction to ensure consistency
- If stat update fails, game operation should still succeed (stats are secondary)

## Division-by-Zero and Empty History Handling

- Accuracy calculations: Check if denominator is 0 before division
- Return `null` for accuracy if no answers yet (or 0, depending on UX preference)
- Best/worst scores: Handle null values (no games completed yet)
- Average score: Return 0 if `totalGamesPlayed === 0`
- Display "N/A" or "-" in frontend for null values

## Idempotency Considerations

- Stat updates are idempotent by design (increment operations)
- Multiple calls to update same stat will correctly accumulate
- Streak updates are stateful (depend on previous streak state)
- Game completion should only be counted once per game
- Use game state (COMPLETED) as guard to prevent duplicate stat updates

## Notes

- Username is set once during signup and cannot be changed (out of scope)
- Email remains the unique identifier for authentication
- Username does NOT need to be unique (multiple users can have same username)
- Stats are only updated for COMPLETED games (not PENDING, ACTIVE, ELIMINATED)
- Stats persist across game sessions (career-level, not per-game)

- Stats must remain correct even if a game fails mid-session (only completed games count)
