# Phase 12: Integrate Cluebase API for Runtime Clue Fetching

## Description

Integrate the Cluebase API into the game creation flow so that when a game is started, the backend fetches Jeopardy and Double Jeopardy clues from the Cluebase API at runtime, normalizes and persists the selected categories and clues to the database, and then initializes the game using only the stored data for the remainder of gameplay. This eliminates the need for pre-ingesting clues and allows games to be created with fresh clue data from the API.

## Implementation Algorithm

### Clue Fetching and Persistence Flow

1. **Fetch Clues from Cluebase API**
   - For each round (Jeopardy, Double Jeopardy):
     - Call Cluebase API to fetch clues (may need multiple requests to get enough clues)
     - Filter clues to ensure:
       - Non-null clue text (question)
       - Non-null correct response (answer)
       - Valid dollar value matching round requirements
     - Collect clues until we have enough to form a complete board (6 categories × 5 clues = 30 clues per round)

2. **Normalize Clue Data**
   - Map Cluebase API response fields to internal Clue model:
     - `clue` or `question` → `question`
     - `answer` or `response` → `answer`
     - `category` → `category`
     - `value` → `value` (ensure it matches round: 200/400/600/800/1000 for Jeopardy, 400/800/1200/1600/2000 for Double Jeopardy)
     - `daily_double` → `dailyDouble` (boolean)
     - `round` → `round` (JEOPARDY or DOUBLE_JEOPARDY)
   - Validate all required fields are present and non-empty

3. **Persist Clues to Database**
   - For each normalized clue:
     - Check if clue already exists using duplicate detection index (round, category, question, answer)
     - If exists, use existing Clue record
     - If not exists, create new Clue record
   - Use transaction to ensure atomicity
   - Return array of Clue records (existing or newly created)

4. **Select Categories and Clues**
   - From persisted clues, select 6 unique categories
   - For each category, ensure we have clues for all 5 required values
   - Verify Daily Double requirements:
     - Jeopardy: exactly 1 Daily Double across all selected clues
     - Double Jeopardy: exactly 2 Daily Doubles across all selected clues
   - If requirements cannot be met, fetch additional clues from API and retry

5. **Create Game Board**
   - Proceed with existing game creation logic:
     - Create GameClue records linking game to selected Clue records
     - Update game state to ACTIVE

### Error Handling

- **Cluebase API Failures**
  - Network errors: Retry with exponential backoff (max 3 retries)
  - Rate limiting: Implement rate limit handling or queue requests
  - Invalid responses: Log error, return meaningful error message to user
  - Insufficient clues: If API doesn't return enough clues, fail game creation with clear error

- **Database Persistence Failures**
  - Transaction rollback on any failure
  - Duplicate detection: Use existing clue if duplicate found (idempotent)
  - Validation errors: Reject invalid clues, continue with valid ones

- **Board Construction Failures**
  - If cannot form valid board (insufficient categories/clues, wrong Daily Double count):
    - Attempt to fetch more clues from API
    - If still cannot form board, fail with descriptive error

### Database Integration
- Use existing PrismaService for database operations

### Game Service Integration
- Inject CluebaseService into GameService constructor
- Modify `startGame()` to call Cluebase API before selecting categories
- Maintain existing game creation logic after clues are persisted
- Ensure backward compatibility: if Cluebase API fails, provide clear error (don't fall back to empty database)

## Data Flow

1. User calls `POST /games/:id/start`
2. GameService.startGame() is invoked
3. For Jeopardy round:
   - Fetch clues from Cluebase API
   - Normalize and persist to database
   - Select 6 categories with complete clue sets
   - Verify Daily Double count (exactly 1)
4. For Double Jeopardy round:
   - Fetch clues from Cluebase API
   - Normalize and persist to database
   - Select 6 categories with complete clue sets
   - Verify Daily Double count (exactly 2)
5. Create GameClue records for all selected clues
6. Update game state to ACTIVE
7. Return updated game

## Constraints and Considerations

- **Clue Immutability**: Once persisted, Clue records cannot be modified (enforced by schema)
- **Duplicate Prevention**: Use existing index to prevent duplicate clues in database
- **API Rate Limits**: May need to implement rate limiting or caching if Cluebase API has limits
- **Network Reliability**: Implement retry logic for transient network failures
- **Data Validation**: Strictly validate all clue data before persistence
- **Daily Double Requirements**: Must satisfy exact Daily Double counts (1 for Jeopardy, 2 for Double Jeopardy) or fail game creation
- **Performance**: Clue fetching adds latency to game start; consider async processing or caching strategies if needed
